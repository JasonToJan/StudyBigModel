## 1. 一个 Transformer block 的通用骨架是什么？（四大件）

四大件：**注意力层**（词间交换信息）、**FFN**（各词独立消化）、**残差连接**（把进层前的自己加回输出，保底通道）、**LayerNorm**（把数值拉回正常范围防炸）。

套娃公式：**Block = 注意力 → FFN，两个部件外各包一层（残差 + 归一化）**。

## 2. Encoder block 和 Decoder block 在结构上差在哪？

- **Encoder**（BERT 系）：双向自注意力 + FFN，一层的简单结构；双向 = 左右都能看，理解力强，但没有自回归出口
- **Decoder**（原版/T5）：三层——**带掩码的自注意力**（只能看已生成的左边）+ **交叉注意力**（Decoder 特有）+ FFN
- 差异核心：Decoder 多了交叉注意力，且自注意力带掩码

## 3. 原版 Decoder 里的"交叉注意力"是干什么的？

**拿正在生成的半成品，去查阅 Encoder 的理解结果**——"写译文的人，一边写、一边回头查原文笔记"。

机制与自注意力完全相同，唯一区别：**Q 来自生成侧的词，K/V 来自 Encoder 输出的理解向量**。翻译时生成 "love" 就拿它的 Q 去对齐原文"爱"的向量并吸收。

## 4. Decoder-only 把结构砍到最简，为什么反而赢了？

01 模块四条：任务统一（万物皆接龙）、数据白嫖（一切文本都是训练题）、结构简单、规模化验证。

今天追加两条技术理由：
1. **训练信号效率**：一条 N 个 token 的数据，Decoder-only 每个位置都产生一个"预测下一个"的训练信号（N 个）；Encoder-Decoder 只有 Decoder 侧有信号
2. **KV Cache 友好**：单流结构，缓存机制天然简单，推理提速容易做

## 5. 模型的 config.json 里，哪些数字对应"架构规模"？

| 字段 | 管什么 |
|---|---|
| `hidden_size` | token 向量维度（语义坐标长度） |
| `num_hidden_layers` | 堆多少层 Block（车间层数） |
| `num_attention_heads` | 并行开几场注意力会 |
| `max_position_embeddings` | 位置座次上限 ≈ 上下文窗口 |
| `vocab_size` | 词表大小（候选池人数） |
