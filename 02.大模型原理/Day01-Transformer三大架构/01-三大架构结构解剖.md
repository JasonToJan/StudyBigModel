# 01. 三大架构结构解剖：从"拼法"到"图纸"

> 02 模块学习笔记 · Day01 · 第一篇 ｜ 阅读时间约 20 分钟
> 目标：01 模块你已经知道三种架构是"三种拼法"；今天打开图纸，看清每种 block 里积木到底怎么组合、差在哪一块。

---

## 一、先说结论：差异不在积木种类，而在两件事

01 模块 Day2 说：Encoder 只读、Encoder-Decoder 读+写、Decoder-only 只写。

今天把这句话升级成工程语言。三种架构用的是**同一套积木**（Day2 学的注意力 + FFN），真正的差异只有两条：

> 🔑 **差异一：注意力掩码方向**（谁能看谁——双向 vs 单向，Day05 细讲）
> **差异二：block 里装了几层、有没有"交叉注意力"这块特殊积木**

记住这两条，下面所有结构图你都能自己推出来。

---

## 二、通用骨架：每个 block 都有的四大件

先复习 01 模块 Day2 第 4 篇的 block 内部。任何 Transformer block，剥开都是四件套：

```
输入向量
  │
  ▼  ① 注意力层 —— 词与词之间交换信息
  │     （残差连接 + LayerNorm 保驾护航）
  ▼  ② FFN 前馈网络 —— 每个词独立消化刚吸收的信息
  │     （残差连接 + LayerNorm 保驾护航）
  ▼
输出向量
```

- **注意力层**：开会（本模块 Day04~07 的主角）
- **FFN**：消化（Day03 的主角，顺带聊"FFN 是不是知识库"这个有趣问题）
- **残差连接**：把"进入这一层之前的自己"加回输出——保底通道，深网络不迷路（Day03 细讲）
- **LayerNorm**：把数值拉回正常范围，防止越乘越大炸掉（Day03 细讲）

套娃公式（背下来）：

> **Block = 注意力 → FFN，两个部件外各包一层（残差 + 归一化）**

三种架构的全部差异，都发生在这个公式的"注意力"格子里——装的是哪种注意力、装了几次。

---

## 三、Encoder block：一层的简单结构

BERT 系的 block 最简单：

```
Encoder Block
├── 双向自注意力   ← 全员开会，左右都能看
└── FFN
（每个部件外：残差 + LayerNorm）
```

- **双向** = 掩码方向全开：处理"它"时，前后文都能看——所以理解力强
- 整个模型 = 这个 block 堆 N 层（bert-base 是 12 层）
- 产出不是文字，是每个位置的"深度理解向量"

适合：分类、检索、语义匹配。不适合生成——没有自回归出口。

---

## 四、Decoder block（原版）：三层结构，今天的主角

2017 年原版 Transformer 和 T5 这类"读+写"模型，解码器 block 比编码器**多一层**：

```
Decoder Block（原版，三层）
├── ① 带掩码的自注意力   ← 生成侧内部开会：只能看已生成的左边
├── ② 交叉注意力（Cross-Attention）★ 特有积木
└── ③ FFN
```

重点理解第 ② 层。交叉注意力干的事，用翻译场景一句话讲透：

> **写译文的人，一边写（① 自注意力），一边回头查原文笔记（② 交叉注意力）。**

它的工作方式和你已经会的自注意力**一模一样**，只有一点不同——**Q 和 K/V 来自不同的地方**：

| | Q（需求） | K/V（被查的干货） |
|---|---|---|
| 自注意力 | 当前词自己 | 同一句话里的其他词 |
| 交叉注意力 | 正在生成的译文词 | **Encoder 输出的理解向量** |

流程走一遍（翻译"我爱北京"→"I love Beijing"）：

1. Encoder 把"我爱北京"加工成一排理解向量（原文笔记）
2. Decoder 生成到"love"时：先在已生成的"I"之间开内部会（①），再拿"love"的 Q 去**查 Encoder 的笔记**（②）——"我现在写的这个词，该对齐原文的哪个词？"——对上"爱"的向量，吸收它，最后 FFN 消化（③）
3. 生成"Beijing"时再查一遍，这次对上"北京"

> 🔑 交叉注意力 = **自注意力的变体：Q 从生成侧来，K/V 从 Encoder 侧来。** 没有新机制，只是"跨桌开会"。

## 五、Decoder-only：把图纸砍到最简

GPT 系的 block，对比原版 Decoder，做了一次"断舍离"：

```
Decoder-only Block
├── 带掩码的自注意力   ← 只能看左边（因果掩码）
└── FFN
（交叉注意力：整块删除）
```

**为什么敢删交叉注意力？** 因为 Decoder-only 里"读"和"写"发生在**同一条序列**上——你输入的 prompt 就在已生成的左边，生成时天然"看得到"。不需要 Encoder 另开一桌再跨桌查阅了。

**为什么砍掉后反而统一了江湖？** 01 模块讲过四条（任务统一、数据白嫖、结构简单、已验证）。今天补两个更技术的：

1. **训练信号效率**：Decoder-only 处理一条 N 个 token 的序列，**每个位置都在做"预测下一个"的练习**——一条句子贡献 N 个训练信号。而 Encoder-Decoder 只有 Decoder 侧有信号，Encoder 侧的任务还要额外设计（填空式）。同样的算力，Decoder-only 的"学习密度"更高
2. **KV Cache 天然友好**：单流结构，生成时只需缓存"左边已算过的东西"就能高速续写；没有 Encoder 和交叉注意力两个需要协调的部件（这条在 Day09 讲 KV 缓存时你会彻底体会到）

## 六、读 config.json：架构参数对上号

每个开源模型都带一份 `config.json`——就是这张图纸的**参数清单**。今天只认五个最常用的字段（以 Qwen2.5-7B 为例的典型值）：

| 字段 | 典型值 | 它管什么 | 对应你的旧知识 |
|---|---|---|---|
| `hidden_size` | 3584 | 每个 token 向量的维度（语义地图的坐标长度） | Day2 的"4096 维"同款概念 |
| `num_hidden_layers` | 28 | 堆多少层 Block（车间层数） | "模型有 32 层"说的是它 |
| `num_attention_heads` | 28 | 同时开几场注意力专项会 | Day2 的"32 heads" |
| `max_position_embeddings` | 32768 | 位置编码的座次上限 | 上下文窗口（Day02 讲怎么来的） |
| `vocab_size` | ~152000 | 词表多大（候选池人数） | Day3 概率表的行数 |

实操 2 会让你亲手指认一遍。以后看模型发布文说"128K 上下文、80 层"，你脑子里应该能浮现这张表。

## 七、本篇小结

1. 三种架构的差异 = **掩码方向**（谁能看谁）+ **block 组合**（装几层、有无交叉注意力）
2. 通用骨架四大件：**注意力 + FFN + 残差 + LayerNorm**；套娃公式背下来
3. 原版 Decoder 三层：掩码自注意力 → **交叉注意力**（Q 来自生成侧、K/V 来自 Encoder 的理解向量）→ FFN；"写的人一边写一边查原文笔记"
4. Decoder-only 删掉交叉注意力：读写同序列，天然不需要跨桌；赢在**训练信号效率 + KV Cache 友好**（追加 01 模块的四条）
5. config.json = 图纸的参数清单：hidden_size / layers / heads / max_position / vocab_size
