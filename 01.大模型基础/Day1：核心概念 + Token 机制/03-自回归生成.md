# 03. 自回归生成：为什么答案是一个字一个字"蹦"出来的

> Day1 学习笔记 · 第三篇（收官）｜ 阅读时间约 10 分钟
> 目标：读完这篇，你能解释流式输出的底层原理、为什么模型"改不了口"，以及同一个问题为什么每次答案不一样。

---

## 一、先说结论：模型从不"打腹稿"

直觉上，你以为模型是这样工作的：

```
收到问题 → 停下来认真想好一整段话 → 一次性告诉你   ❌ 错
```

实际是这样：

```
收到问题 → 预测 1 个 token → 预测下 1 个 → 再下 1 个 → …… → 说"完了"   ✅ 对
```

**模型在任何时刻，只做一件事：根据前面已有的全部内容，预测下一个 token。** 它没有"整段话"的概念，长回答是把这个单步动作重复成百上千次的结果。

这个机制有个术语：**自回归（Autoregressive）**——"自己生成的输出，回头变成自己的输入"。

---

## 二、自回归循环：一个"贪吃蛇"游戏

把它想象成贪吃蛇：

```
输入: "今天天气真"
  ↓ 模型预测下一个 token: "好"
输入: "今天天气真好"
  ↓ 预测下一个: "，"
输入: "今天天气真好，"
  ↓ 预测下一个: "适合"
输入: "今天天气真好，适合"
  ↓ ……继续
  ↓ 直到预测出"结束"的特殊 token（如 <eos>），生成停止
```

三个要点：

1. **每生成一个 token，就把它拼回输入末尾**，作为下一轮预测的依据——蛇越吃越长
2. **什么时候停？** 当下一个"最高概率 token"是特殊的**结束符**（eos, end of sequence）时。模型学过"回答到此为止该说什么"——连闭嘴都是预测出来的
3. 上一篇学的 Token 在这里是主角：模型每次生成的不是"一个字"，而是**一个 token**

> 🔑 一句话：**生成 1000 字的回答 = 玩了上千轮"接下一句"游戏，仅此而已。**

---

## 三、流式输出：你看到的"打字机效果"不是特效

为什么网页版 AI 的回答是一段一段往外蹦的？

不是前端做的"打字机动画"，而是**模型真的就是逐 token 生成的**。产品把每生成好的一小段就立刻推给你显示，这叫**流式输出（Streaming）**。

这带来一个重要推论——** 首 token 时间（TTFT, Time To First Token）**：

- 传统接口：等整个回答全部生成完才返回，用户盯着空白屏幕干等
- 流式接口：第一个 token 刚生成就返回，用户几百毫秒就看到内容开始滚动

做应用开发时，**对话类产品几乎永远用流式**，这是体验的生死线。后面学 API 调用（04 模块）时会亲手实现 `stream=True`。

## 四、为什么模型"改不了口"：覆水难收

自回归还有一个深远后果：**已生成的 token 无法撤回**。

模型写到第 500 个 token 时，就算"感觉"前面写错了，它也不能回头修改第 300 个 token——因为第 300 个已经拼进输入里，成为既定事实。它只能顺着错下去。

这解释了几个常见现象：

| 现象 | 自回归视角的解释 |
|---|---|
| 前面说错一个数，后面越圆越歪 | 错误 token 拼回输入后，后续预测全部"基于错误继续"，错误滚雪球 |
| 让模型"检查一遍你的回答"，有时能纠错 | 把已生成内容重新摆到桌上（新一轮生成），相当于给了它"重新看着草稿誊写"的机会 |
| 长回答比短回答更容易跑偏 | 步数越多，累积偏航的概率越大 |

> 🔑 一句话：**模型是"一条道走到黑"的生成方式，工程上要靠重试、校验、让它自我复查来兜底。**

顺带解开第一篇留下的悬念：同一个问题每次答案不一样，是因为每一步预测的不是"唯一答案"而是**概率分布**，产品从分布里抽样（怎么抽、抽多随机，是 Day3 推理参数的内容）。自回归 + 概率抽样，意味着每次生成的路径都不同。

## 五、一个工程彩蛋：KV Cache（知道即可）

贪吃蛇每吃一口都要重新审视全身吗？

按最朴素的做法，生成第 N 个 token 时要把全部输入**重新计算一遍**——1000 token 的对话就要重复算 1000 次前 999 个 token，太浪费了。

工程上的解法叫 **KV Cache**：把前面 token 已经算好的中间结果缓存起来，每步只算新增的那个 token。你不需要懂细节（Day2 Transformer 讲完注意力机制后自然就懂了），只需知道两件事：

- 这是推理为什么能快到"逐字往外蹦"的关键优化
- 各平台 API 的"上下文缓存/前缀缓存"计费折扣，底层就是复用了这类计算

## 六、Day1 全篇总结（三条主线串起来）

1. **第一篇**：模型是概率生成器，不是检索器——所以有幻觉，所以要工程驯服
2. **第二篇**：模型眼里只有 token 序列——所以成本、速度、窗口都按 token 算
3. **本篇**：模型一个 token 一个 token 自回归生成——所以流式、所以改不了口、所以每次答案不同

> 合起来就是那句话：**模型眼里没有文字，只有 token 序列；它的工作只有一个——预测下一个 token。**
