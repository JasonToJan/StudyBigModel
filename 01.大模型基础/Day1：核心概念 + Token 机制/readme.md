## 二、学习内容（约 90 分钟）

### 1. 大模型核心概念（30min）

- **LLM 是什么**：基于海量文本训练的"下一个词预测器"
  - 它没有数据库、不联网（原生状态）、不是"检索答案"而是"概率生成"
- **训练 → 对齐 → 使用** 三阶段概览（今天只建立印象，细节在后面阶段展开）
  - 预训练（学知识）→ SFT/RLHF（学听话）→ 推理部署（提供服务）
- **基座模型 vs 对话模型**：Qwen-72B 和 Qwen-72B-Chat 的区别
- **能力边界**：为什么会幻觉、知识有截止日期、数学/逻辑是短板

### 2. Token 机制（40min，今日重点）

- **什么是 Token**：模型处理文本的最小单位，介于"字"和"词"之间的碎片
- **为什么需要 Tokenizer**：模型只能理解数字（token id），Tokenizer 负责文本 ↔ 数字互转
- **中文 vs 英文的 token 效率差异**：中文通常 1 字 ≈ 1~2 token，英文 1 词 ≈ 1 token —— 这直接影响成本
- **上下文窗口**：模型一次能"看到"的 token 上限
  - 输入（prompt + 历史）+ 输出（回答）共享这个窗口
  - 超限会发生什么：截断、报错、早期内容被"遗忘"
- **Token 与钱的关系**：API 按 token 计费，输入/输出单价不同

### 3. 自回归生成直观理解（20min）

- 模型每次只生成**一个 token**，生成后把它拼回输入，再预测下一个
- 理解为什么回答是"逐字蹦出来"的（流式输出的底层原因）
- 理解为什么模型"改不了口"——已生成的 token 无法撤回

## 三、实操任务（约 60 分钟）

### 实操 1：体验 Tokenizer（20min）

- 打开 OpenAI 官方分词器可视化工具：https://platform.openai.com/tokenizer
  （或 HuggingFace 的 tokenizer 在线演示）
- 分别输入：一段英文、一段中文、一段代码、一个 emoji
- 记录：各消耗多少 token？中文是不是更"贵"？

### 实操 2：API 控制台观察 token 消耗（20min）

- 注册任一国内大模型平台（如智谱/DeepSeek/Qwen），拿到 API Key
- 调用一次对话（可用平台自带的调试页），观察返回里的 `usage` 字段
- 记录：prompt_tokens / completion_tokens / total_tokens 分别是什么

### 实操 3：上下文窗口体验（20min）

- 在网页版大模型（任意）对话中持续追问，观察什么时候它"忘记"了最早说的话
- 思考：这就是上下文窗口限制的直观表现
