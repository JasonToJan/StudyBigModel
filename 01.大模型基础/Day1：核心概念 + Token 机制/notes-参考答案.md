## 1. 什么是大语言模型（LLM）？它和传统程序的本质区别是什么？

LLM 是基于海量文本训练出来的**"预测下一个 token"的概率机器**。

与传统程序的本质区别：

| | 传统程序 | LLM |
|---|---|---|
| 行为 | 确定性：同样输入必然同样输出 | 概率性：同样输入输出可能不同 |
| 知识 | 写死在代码/数据库，靠查询获得 | 压缩在参数里，靠生成获得 |
| 出错方式 | 崩溃报错（显性） | 幻觉跑偏（隐性且看起来自信） |

## 2. 什么是 Token？为什么模型不直接认识"字"或"词"？

Token 是模型处理文本的**最小单位**，是介于字和词之间的碎片（如"人工智能"可能切成"人工+智能"）。

模型不直接认识字词，因为它是跑在显卡上的神经网络，**只能处理数字**。文字必须先由 Tokenizer 切成 token，再查词表换成编号（token id），模型从头到尾处理的都是数字序列。

## 3. 一段中文/英文文本大约消耗多少 Token？

- 英文：1 个词 ≈ 1 token
- 中文：1 个字 ≈ 1~2 token（tokenizer 训练语料以英文为主，中文字常被拆碎）
- 口诀：**500 字中文 ≈ 500~1000 token**；空格和标点都算

## 4. 什么是上下文窗口（Context Window）？超了会怎样？

模型一次能"看到"的 token 总量上限。关键：**输入（系统提示+历史+当前问题）和输出共享**这个窗口。

超限的三种表现：
1. 输入本身超限 → API 直接报错
2. 接近上限 → 平台悄悄截断最早内容 → 模型"失忆"、行为突变（最隐蔽）
3. 输出空间不足 → 答到一半被掐断（finish_reason=length）

## 5. 模型是怎么"一个字一个字"生成回答的？（自回归的直观理解）

**自回归**：模型每次只根据前面全部内容预测 1 个 token → 生成后把它拼回输入 → 再预测下一个……循环往复，直到预测出"结束符"（eos）或撞上 max_tokens。

所以：生成 1000 字 = 玩了上千轮"接下一句"游戏；打字机效果（流式输出）不是动画，是真实生成节奏；已生成的 token 拼回输入成既定事实，**改不了口**。
