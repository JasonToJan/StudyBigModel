# 01. 大模型核心概念：它到底是个什么东西？

> Day1 学习笔记 · 第一篇 ｜ 阅读时间约 15 分钟
> 目标：读完这篇，你能用大白话向别人解释"大模型是什么、它怎么工作、为什么它会一本正经地胡说八道"。

---

## 一、先说结论：大模型是一个"超级接话机器"

忘掉电影里的 AI 形象。一个语言大模型（LLM, Large Language Model）的本质简单到让人意外：

> **给定前面所有的字，预测下一个字最可能是什么。**

就这么一件事。

你输入"今天天气真"，它会告诉你下一个字大概率是"好"。你输入"床前明月"，它会说下一个字是"光"。把这个游戏重复几千亿次，就能写出文章、代码、报告——**生成一整段回答，不过是把"预测下一个字"重复了很多遍**。

这带来一个关键认知：

> 模型不是在"检索答案"，而是在"概率生成答案"。

它没有内置数据库，不查资料（原生状态下也不联网）。它说出"光合作用是植物……”是因为训练数据里这样的句子出现得太多了，而不是它"知道"光合作用。这个区别，是理解大模型一切怪行为的钥匙。

---

## 二、大模型是怎么炼成的：三个阶段

一个大模型从无到有，大致经历三步。今天只需要建立印象，每一步在后续课程都会展开。

### 阶段 1：预训练（Pre-training）—— 学知识

- 把互联网上数万亿 token 的文本（网页、书籍、代码……）喂给模型
- 任务只有一个：不断玩"预测下一个词"的游戏
- 玩到最后，模型为了预测得准，被迫"学会"了语法、事实知识、逻辑关系、甚至编程
- **产出：基座模型（Base Model）**——一个知识渊博但不会"聊天"的模型

类比：一个读完了整座图书馆的人，但你问他问题，他只会续写，不会好好回答。

### 阶段 2：对齐（Alignment，即 SFT / RLHF）—— 学听话

- 用高质量的"指令 → 回答"数据教模型：人类提问时，应该怎么回应
- 再通过人类反馈进一步调整：哪种回答更受欢迎
- **产出：对话模型（Chat Model / Instruct Model）**

类比：图书馆怪才接受了客服培训，学会了礼貌、格式、拒绝不当请求。

### 阶段 3：推理部署（Inference）—— 上班干活

- 模型部署到服务器，通过 API 或网页对外提供服务
- 你平时用的 ChatGPT、智谱清言、DeepSeek 对话框，都是这个阶段
- **这个阶段才是我们应用开发工程师的主战场**：调 API、写 prompt、搭 RAG/Agent

> 💡 记住这条流水线：**预训练（学知识）→ 对齐（学听话）→ 推理（干活）**。面试和后续学习会反复遇到它。

---

## 三、基座模型 vs 对话模型：名字里的门道

开源模型的名字不是随便起的，看名字就能分辨阶段：

| 名字 | 类型 | 你问"你是谁"它会…… |
|---|---|---|
| Qwen-72B | 基座模型 | 可能续写出一篇新闻或把问题重复一遍 |
| Qwen-72B-Chat / -Instruct | 对话模型 | 正常回答"我是通义千问……" |

- **带 Chat / Instruct / ChatML 字样的 = 对话模型**，日常使用选它
- 基座模型不是"坏"，它擅长的是**续写**而非对话，微调（Step10）时反而以它为起点
- 参数量（72B 中的 B = Billion，即 720 亿参数）代表模型"脑容量"，越大通常越强也越贵

## 四、能力边界：为什么它会一本正经地胡说八道

这一节最重要。理解了边界，你才知道为什么后续要学 RAG（外挂知识）、prompt 约束（控制行为）、Agent（外挂工具）。

### 1. 幻觉（Hallucination）—— 头号问题

**定义**：模型生成看似合理、实际错误的内容。

**根源**（记住第一条就够了）：它是概率生成，不是事实检索。当它"不知道"时，它不会留白，而是生成**统计上最像答案的话**。

例：你问一个冷门问题，模型会编造一个格式完美、引用齐全、但根本不存在的论文——因为它学过"回答学术问题长什么样"。

> 🔑 一句话：**模型不会说"我不知道"，除非你教它说。**

### 2. 知识截止（Knowledge Cutoff）

训练数据有截止日期。今天之前发生的事，模型一无所知——但如果你问它，它可能照样编一个答案。这就是为什么需要 RAG 给它外挂实时知识库。

### 3. 数学与精确逻辑是短板

"预测下一个字"不等于精确计算。让模型算 38471 × 2953，它是在"凭语感写数字"。精确计算需要工具（这就是 Agent 调用计算器的理由）。

### 4. 原生不联网、无记忆

- 每次对话都是全新的：关掉窗口，它不记得你是谁（产品层面的"记忆"是额外工程实现的）
- 不会主动上网查资料（带搜索的功能是工程外挂，不是模型本身的能力）

## 五、和传统程序的本质区别（工程师视角）

作为未来的 LLM 应用工程师，这个对比值得刻进脑子：

| | 传统程序 | LLM 应用 |
|---|---|---|
| 行为 | 确定性：if-else，同样的输入必然同样的输出 | 概率性：同样的输入，输出可能不同 |
| 知识 | 写死在代码/数据库里，查询得到 | "压缩"在参数里，生成得到 |
| 出错方式 | 崩溃、报错（显性） | 幻觉、跑偏（隐性，且看起来很自信） |
| 工程核心 | 保证逻辑正确 | 约束与兜底：prompt 设计、输出校验、防幻觉 |

**LLM 应用开发的本质，就是用工程手段，把一个概率性的、会犯错的生成器，驯服成一个可靠的产品组件。** 这条主线贯穿整个学习路线。

---

## 六、本篇小结

1. LLM = 超级接话机器，核心机制是**预测下一个 token**
2. 成长流水线：**预训练 → 对齐 → 推理部署**；名字带 Chat/Instruct 的才是对话模型
3. 四大边界：**幻觉、知识截止、算不准、无记忆不联网**——它们分别解释了为什么需要 prompt 约束、RAG、工具调用、记忆工程
4. 应用工程师的使命：给概率机器套上工程缰绳
