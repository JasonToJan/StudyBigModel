## 一、先说结论：五天知识，其实是一条流水线上的五段

Day1~Day4 我们学了：Token、Transformer、自回归、推理参数、对齐、选型。看起来概念很多，但它们全部发生在**同一条流水线**的不同段落上：

```
┌─────────────────── 输入侧 ───────────────────┐
│ 你的文字："帮我写一首关于秋天的诗"              │
│    ↓ ① 切分 [Day1]                            │
│ token 序列 [12543, 8871, …]                   │
│    ↓ ② 上地图、发座号 [Day2]                  │
│ Embedding 向量 + 位置编码                      │
└──────────────────────────────────────────────┘
                     ↓
┌─────────────────── 计算侧 ───────────────────┐
│    ↓ ③ N 层 Block 加工 [Day2]                 │
│ 每层：全员开会（Q/K/V 注意力）+ 消化（FFN）    │
└──────────────────────────────────────────────┘
                     ↓
┌─────────────────── 输出侧 ───────────────────┐
│    ↓ ④ 打分 → 概率表 [Day2 输出层]            │
│ "秋" 31% ｜"的" 12% ｜"风" 9% ｜…             │
│    ↓ ⑤ 参数遥控，挑一个 [Day3]                │
│ temperature 分蛋糕 → top_p 圈人 → 掷骰子      │
└──────────────────────────────────────────────┘
                     ↓
┌─────────────────── 循环与交付 ───────────────┐
│    ↓ ⑥ 拼回输入，回到 ③ [Day1 自回归]         │
│ 重复几十上百次，直到预测出"结束符"              │
│    ↓ ⑦ 逐 token 流式推到你的屏幕 [Day1]       │
│ "秋"… "风"… "起"… —— 你看到的打字机效果       │
└──────────────────────────────────────────────┘

        ↑ 以上之所以是"听话的助手"而不是"续写怪"：
┌─────────────────── 底座 ─────────────────────┐
│ [Day4] 预训练（学知识）→ SFT（教格式）         │
│        → RLHF/DPO（教偏好）→ 三看选型上岗     │
└──────────────────────────────────────────────┘
```

下面把每段的知识点重新走一遍——这次不是学新东西，而是**确认每一段你都还记得它为什么存在**。

## 二、输入侧：模型接住你的话（Day1 + Day2）

### ① 切 token（Day1 第 2 课）

文字变编号。关键记忆点：**模型眼里没有文字，只有 token 序列**；中文 1 字 ≈ 1~2 token；空格标点都算；一切成本按 token 算。

### ② 上地图、发座号（Day2 第 2 课）

- **Embedding**：编号没有含义，要变成"语义地图上的坐标"才有含义——意思相近 = 距离相近（RAG 语义检索的根基）
- **位置编码**：全员开会前发"座位号"，否则分不清"猫吃鱼"和"鱼吃猫"；座次上限是窗口限制的原因之一

**自问**：为什么不能跳过这两步直接把 token id 喂给神经网络？（提示：id 只是门牌号，不含语义；注意力天然无序。）

---

## 三、计算侧：理解在这里发生（Day2）

### ③ N 层 Block（Day2 第 2、4 课）

每层两件事：**开会（自注意力）+ 消化（FFN）**。

自注意力的三个动作：**环顾四周 → 判断相关度（Q 对 K 打分）→ 按比例吸收 V**。"它"锁定"老鼠"、多头各管一个侧面——理解就是这样一层层滚出来的，浅层管语法、深层管语义。

**自问**：Q、K、V 用招聘会类比分别是什么？三套"滤镜"参数是哪来的？（训练学出来的——微调调的就是它们。）

---

## 四、输出侧：从理解到文字（Day2 + Day3）

### ④ 概率表（Day2 第 2 课 / Day3 第 1 课）

最后一个位置的向量对**全词表打分**（logits → softmax）——模型只负责报出概率表，**没有"标准答案"的概念**。

### ⑤ 参数遥控（Day3 全部）

把表变成字，由采样策略决定，参数各司其职：

| 旋钮 | 管什么 | 一句话 |
|---|---|---|
| temperature | 池内怎么分蛋糕 | 低温赢家通吃，高温众生平等；**不是智力旋钮** |
| top_p / top_k | 谁有资格上桌 | 累计概率圈人（top_p 动态伸缩，现代默认） |
| max_tokens / stop | 何时停 | 保险丝和闭嘴暗号 |
| penalties | 防复读 | 需要重复的场景（代码/JSON）要关掉 |
| seed / stream | 复现与交付 | 调试固定 seed；产品对话必开流式 |

**自问**：输出乱码/生僻字，排查顺序是什么？（先压温度 → 再压 top_p。）

## 五、循环与交付：打字机效果的真相（Day1）

### ⑥ 自回归循环

挑出的 token **拼回输入**，回到第 ③ 步再算下一个——贪吃蛇越吃越长。直到预测出**结束符**（eos），或撞上 max_tokens 被 `finish_reason=length` 掐断。

### ⑦ 流式交付

每个 token 刚生成就推给你——**打字机效果不是动画，是真实生成节奏**。首 token 时间（TTFT）是对话产品的体验生死线。

**自问**：已生成的 token 为什么改不了口？错误为什么滚雪球？（拼回输入成既定事实；工程上靠复查/校验兜底。）

## 六、底座：这一切的前提（Day4）

上面整条流水线能产出"听话助手"，前提是你调用的模型**已经被调教过**：

```
预训练（万亿 token 学知识，产物=只会续写的基座）
   ↓ SFT（几万条满分范文教格式：学行为不学知识）
   ↓ RLHF/DPO（人类排序教偏好：奖励模型=替身评委；DPO 砍中间商）
   ↓ 三看选型（型号→规模→License，够用就好）
   ↓ 上岗：你通过 API 调用的，就是它
```

副作用也要记得：拒答会误伤、谄媚源于人类偏爱附和、对齐税压制续写——prompt 层各有应对。

**自问**：谄媚的根源是什么？（RLHF 用人类打分，人天然偏爱附和。）

## 七、工程视角：全链路上每个位置的"可操作旋钮"

作为应用工程师，你的全部优化手段都挂在这条流水线的某一段上——这张表就是未来 12 个模块的导航图：

| 流水线位置 | 你能动的旋钮 | 属于哪个模块 |
|---|---|---|
| 输入侧 | prompt 设计、few-shot、历史管理 | 03 prompt |
| 检索增强 | 向量检索、知识库 → 补充进输入 | 05~06 RAG |
| 模型底座 | 选型、微调 | 10~11 微调 |
| 输出侧 | temperature / top_p / penalties / max_tokens | 04 API（马上学） |
| 交付侧 | 流式、重试、输出校验 | 04 / 08 |
| 循环层 | 工具调用、多轮编排 | 07~08 Agent |

> 🔑 **LLM 应用开发 = 在流水线的不同位置插上不同的旋钮。** 以后学任何新技术，先问：它卡在这条链的哪一段？

## 八、模块 01 总结：三个大问题的答案

1. **模型是什么？**（Day1）——概率生成器，不是检索器；有幻觉、有知识截止、算不准、无记忆
2. **它怎么工作？**（Day1~3）——token 进，概率表出，参数遥控，自回归循环，流式交付
3. **它怎么被调教出来的？**（Day4）——预训练学知识，SFT 教格式，RLHF/DPO 教偏好，选型三看上岗
