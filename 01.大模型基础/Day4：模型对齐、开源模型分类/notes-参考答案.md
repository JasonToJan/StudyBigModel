## 1. 基座模型为什么不能直接当产品用？"对齐"到底在补什么？

基座的本能是**续写不是回答**：问它"北京有什么好吃的"，它可能续写出"上海有什么好玩的？"（训练时见过太多论坛提问帖）；且没有身份、不懂拒绝、不讲格式——知识满分、情商为零。

对齐补的就是这个：**让模型行为符合人类意图**——该回答时回答、该拒绝时拒绝、格式得体。类比：满腹经纶的高材生接受入职培训。预训练教它"怎么说话"，对齐教它"怎么办事"。

## 2. SFT（监督微调）教了模型什么？数据长什么样？

教"回答长什么样"：给模型看成千上万条人工撰写的高质量**（指令 → 满分回答）对话范例**，数据就是 messages 结构（system 人设 / user 问题 / assistant 人工写的标准答案）。

关键认知：**SFT 学的是行为模式，不是知识**（知识在预训练已灌满）——所以数据量远小于预训练且**质量远比数量重要**，几百条精品就能显著改变行为（四两拨千斤）。

## 3. RLHF / DPO 是在教什么？和 SFT 的区别是什么？

教"哪种回答更好"（品味）。SFT 的天花板：范文只能教"合格"，教不了细微优劣。

- **RLHF 四步**：模型一次生成多个回答 → 人类排序 → 训练**奖励模型**（把人类品味压缩成"替身评委"）→ 强化学习优化（以奖励分为 KPI）
- **与 SFT 的区别**：SFT 是看范文模仿，RLHF 是被人类当裁判打分后悟品味
- **DPO** = 砍掉奖励模型这个中间商，直接拿"回答 A 比 B 好"的偏好对学习——更简单稳定便宜，开源社区主流

## 4. 为什么模型会拒答？为什么会"谄媚"？

- **拒答**：拒绝是**被训练出来的技能**（对齐数据大量掺入拒绝场景+话术，RLHF 又持续强化）——技能会用力过猛，误伤合法请求（安全写作、安全测试代码等）。应对：补正当语境、换措辞、换模型
- **谄媚**：RLHF 用**人类打分**训练，而人类标注员天然偏爱附和自己的回答 → 模型学到黑暗法则"顺着用户说=高分"。危害：需要纠错的场景（代码 review、咨询）里变成应声虫。应对：显式授权反驳 + 要求独立推理

## 5. 开源模型生态怎么分类？选型时该看哪几个维度？

**三看**：

1. **型号**（后缀定角色）：无后缀=基座（只续写）；-Chat/-Instruct=对话模型（日常首选）；-Coder=代码；-VL=多模态；embedding 系列=只转向量做检索
2. **规模**：0.5B~3B 端侧 / 7B~14B 中小项目主力 / 32B~72B 生产 / 100B+ 走 API——原则"够用就好"
3. **License**：Apache 2.0 / MIT 可放心商用；自定义许可（Llama 系等）要查条款——**开源 ≠ 免费商用**，用前必查 Model Card

三大谱系：Qwen 型号最全（万金油）、GLM 强对话与 Agent、DeepSeek 强推理与性价比。
