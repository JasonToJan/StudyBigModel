## 二、学习内容（约 95 分钟）

### 1. 对齐总览：从"会说话"到"会办事"（20min）

- 基座模型的尴尬：满腹经纶但只会续写，问它问题可能给你续写出十个新问题
- 对齐（Alignment）的定义：让模型的行为符合人类的意图和偏好
- 两步走框架：**SFT 教格式 → RLHF 教偏好**

### 2. SFT：监督微调，教"回答长什么样"（25min，今日重点之一）

- 指令微调数据：成千上万条高质量的（指令 → 优秀回答）范例
- 直觉理解：给图书馆怪才看几万份"满分客服话术"，模仿即学会
- 数据格式预览（messages 结构），为 04 模块 API 调用打基础

### 3. RLHF / DPO：人类偏好反馈，教"哪种回答更好"（25min）

- SFT 的天花板：范例只能教"什么样"，教不了"更好 vs 更坏"的细微观感
- RLHF 三步：让模型一次生成多个答案 → 人类排序 → 训练奖励模型 → 强化学习优化
- DPO：跳过奖励模型的简化路线，开源社区主流
- 类比：SFT 是看范文抄作业，RLHF 是"老板从两份方案里挑一份，你慢慢悟什么是对的"

### 4. 对齐的副作用：安全税与谄媚（10min）

- 拒答（"我无法协助该请求"）：安全策略的体现，有时会误伤
- 谄媚（Sycophancy）：为了讨好用户而附和错误说法
- 对齐税：对齐后部分能力下降的现象；工程上如何与之共处

### 5. 开源模型分类与选型（15min）

- 三看选型法：**看型号**（基座 vs Chat/Instruct）、**看规模**（0.5B~600B 档位与部署成本）、**看 License**（Apache/MIT 可商用 vs 自定义限制）
- 国内主流谱系速览：Qwen 全家桶、GLM 系列、DeepSeek 系列
- 我们技术栈的选型逻辑回顾

## 三、实操任务（约 60 分钟）

### 实操 1：亲眼观察"对齐的行为"（20min）

- 在网页版对话模型里做三个实验并记录：
  a. 让它续写而不是回答（说"请续写以下文本："）——观察它仍倾向"回答"而非"续写"，这就是对齐的痕迹
  b. 用一个边界请求（如"帮我写一封诈骗短信"）观察拒答话术
  c. 先说"1+1=3 对吧？"再问答案，观察它是否附和（谄媚实验）
- 记录进 `alignment_observation.md`

### 实操 2：选型练习（20min）

- 三个场景选型并写理由（一句理由即可）：
  A. 本地客服知识库问答（RAG），预算有限
  B. 竞品分析报告生成，要求高质量
  C. 手机端离线运行的智能输入联想
- 产出存 `model_selection.md`

### 实操 3：读一个模型的 Model Card（20min）

- 打开 HuggingFace 上任一 Qwen 模型页，找出：参数量、上下文长度、License、是否 Chat 版
- 用自己的话写 3 行摘要
