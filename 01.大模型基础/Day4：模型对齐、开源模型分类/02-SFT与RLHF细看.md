## 一、先说结论：模仿 vs 悟性

| | SFT | RLHF / DPO |
|---|---|---|
| 教什么 | 回答**长什么样**（格式、姿态） | 哪种回答**更好**（品味） |
| 学习方式 | **模仿**：照着范文练 | **反馈**：被打分后悟 |
| 类比 | 书法临帖 | 老板改稿 + 点评 |

上一课搭好了框架，这一课打开两步的引擎盖。

## 二、SFT 细看：临帖式学习

### 1. 数据长什么样

一条 SFT 训练数据 = 一组完整对话。你以后调 API 时见到的 `messages` 结构，和它同源：

```json
{
  "messages": [
    { "role": "system",    "content": "你是一个耐心的编程助教。" },
    { "role": "user",      "content": "Python 的列表和元组有什么区别？" },
    { "role": "assistant", "content": "好问题！主要区别有三点：
        1. 可变性：列表可增删改，元组创建后不可变……" }
  ]
}
```

- **system**：给模型的"人设/规则说明"
- **user**：人类的问题
- **assistant**：人工撰写或精心审核过的**满分回答**

几十万条这样的样本喂进去，任务只有一句话：**学会在对话走到 assistant 位置时，说出这种质量的话。**

### 2. 反直觉的关键认知：数据质量 >> 数据数量

SFT 的数据量**远小于**预训练：

- 预训练：数万亿 token 的互联网文本
- SFT：几万到几十万条精选对话

为什么这么少就够？因为 **SFT 教的是"行为模式"，不是"知识"**——知识早在预训练就灌满了，SFT 只是把"满腹经纶"扳成"对答如流"。姿态的切换，不需要海量数据，只需要**高质量的示范**。

> 🔑 记住这条：**SFT 学行为，不学知识。** 这也是为什么未来你做微调（Step10）时，几十条、几百条精心造的数据就能显著改变模型行为——"四两拨千斤"。

### 3. 两个和你直接相关的落点

- **Prompt 里的 few-shot 示例**（03 模块要学）：在提示词里放几个"问题 → 标准回答"示例让模型模仿——**原理和 SFT 同源，只是把训练搬到了推理时**（不改变模型，只在上下文里临时"临帖"）
- **Step10 微调**：你未来亲手做的，就是缩小版 SFT；数据怎么造是 Step11 的主题

## 三、RLHF 细看：裁判式学习

### 1. SFT 的天花板

范文能教"合格"，教不了"优秀之间的差距"。两个回答都通顺得体，但一个啰嗦、一个精炼；一个瞎编、一个诚实说不知道——**这种细微观感，写不成范文，人类却能一眼分辨**。

### 2. RLHF 的四步流程

```
① 采样     让模型对同一问题生成多个回答（A、B、C、D）
   ↓
② 人类排序 标注员只做一件事：排出 A > C > B > D
   ↓
③ 训练奖励模型（RM） 用几十万条排序数据，训练一个"打分器"，
   让它学会模拟人类的品味 —— 给任何回答打分
   ↓
④ 强化学习  模型不断生成回答 → 奖励模型打分 → 分高就强化、分低就削弱
            （以 PPO 为代表的算法，知道名字即可）
```

### 3. 奖励模型：学会了人类品味的"替身评委"

第 ③ 步是 RLHF 的精髓。人类直接给模型当教练太贵太慢（不能 24 小时盯着一句话一句话地纠偏），于是先训练一个**替身**：

> **奖励模型（Reward Model）= 把人类的排序偏好压缩进另一个网络，让它代替人类打分。**

之后正式训练时，模型对着这个"永不下班、态度一致的评委"反复练习，奖励分就是唯一的 KPI。

类比：教练（人类）先陪练一段时间定下评分标准，然后把这个标准交给助教（RM），助教全职陪练——标准统一、不知疲倦。

### 4. RLHF 贵在哪，DPO 如何接棒

RLHF 的代价：要**同时养多个模型**（正在训练的模型 + 奖励模型 + 参考模型），流程复杂、训练不稳定、算力开销大——基本只有大厂玩得起。

于是开源社区流行起简化版 **DPO（Direct Preference Optimization，直接偏好优化）**：

- **砍掉奖励模型这个中间商**：不训练替身评委，直接拿"回答 A 比 回答 B 好"的偏好对数据，让模型自己直接调整
- 直觉：从"对着助教练习悟标准"简化为"把好坏对比直接摆给你看，你直接改"
- 效果：训练更简单稳定、成本低得多，Qwen / DeepSeek 等开源模型的对齐流程大量采用这类方法

> 🔑 现在回头看：**SFT 是"看范文"，RLHF 是"请教练"，DPO 是"看对比直接悟"。** 三种姿态，一个目标：让模型越来越像人类希望的样子。

---

## 四、本篇小结

1. SFT 数据 = messages 结构的完整对话（system / user / assistant），**质量远比数量重要**
2. SFT 学**行为模式**不学知识——这是"少量数据四两拨千斤"的原因，也是 few-shot prompt 的原理
3. RLHF 四步：采样 → 人类排序 → 训练**奖励模型**（人类品味的替身评委）→ 强化学习优化
4. DPO = 跳过奖励模型的直接偏好学习，简单稳定，开源社区主流
