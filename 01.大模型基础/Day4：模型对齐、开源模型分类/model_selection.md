## 1. 场景 A：本地客服知识库问答（RAG），预算有限

### 三看推理

| 三看 | 结论 |
|---|---|
| 型号 | 检索半边 = **embedding 模型**（bge-m3，Encoder-only，不生成只转向量）；生成半边 = **Instruct 对话模型** |
| 规模 | 客服问答检索为主、生成难度中等 → **7B 档够用**（或 API 低档位）；盲目上 72B = 白烧钱 |
| License | bge-m3（MIT）、Qwen 系（Apache 2.0）→ 商用无风险 |

### 选型结论

- **方案一（自部署）**：bge-m3 做检索 + `Qwen2.5-7B-Instruct` 做生成，量化后一张消费级显卡跑得动，无持续 API 开销
- **方案二（更省心）**：bge-m3 检索 + `deepseek-flash`（API 低价档）做生成，零硬件投入，按 token 付费

**一句话理由**：RAG 场景的生成难度被检索兜住了，"够用就好"原则下 7B / 低档 API 就能给出高质量答案。

---

## 2. 场景 B：竞品分析报告生成，要求高质量

### 三看推理

| 三看 | 结论 |
|---|---|
| 型号 | 长文生成 + 分析推理 → 对话/推理**旗舰** |
| 规模 | 质量优先 → 能力上限优先，**100B+ 档（走 API）**；长报告需要大输出上限（393K 富余） |
| License | API 服务不涉及部署许可问题；按量付费总成本远低于为旗舰买多卡 |

### 选型结论

**`deepseek-v4-pro`，effort 拉到 max。**

**一句话理由**：高质量需求 = 买能力上限，旗舰 API 按量付费是性价比最高的路径；任务低频（写报告），API 总成本可控。

> 关联 Day3：effort/推理档位类似"思考预算"旋钮——高质量分析任务值得调高。

---

## 3. 场景 C：手机端离线运行的智能输入联想

### 三看推理

| 三看 | 结论 |
|---|---|
| 型号 | **Instruct 对话模型**（0.5B 档） |
| 规模 | **0.5B ~ 1.5B**——手机内存和延迟是硬约束，量化后端侧可跑 |
| License | Qwen 小尺寸系列 Apache 2.0，可随 App 商用 |

### 选型结论

**`Qwen2.5-0.5B-Instruct`（或 1.5B），量化后端侧部署。**

**一句话理由**："离线"直接判 API 出局，手机端只塞得下 0.5B~1.5B 档；而输入联想任务简单，小模型完全够用。

> 关键认知：**这个场景证明了"并非所有需求都需要大模型"**——任务难度决定规模下限，硬件约束决定规模上限。

## 4. 三场景速查总表

| 场景 | 选型 | 决定性约束 |
|---|---|---|
| A. RAG 客服问答（预算有限） | bge-m3 + Qwen2.5-7B-Instruct 或 deepseek-flash | 预算 → 够用就好 |
| B. 高质量竞品报告 | deepseek-v4-pro（effort=max） | 质量优先 → 能力上限 |
| C. 手机离线输入联想 | Qwen2.5-0.5B-Instruct 量化端侧 | 离线+硬件 → 小模型是唯一解 |
