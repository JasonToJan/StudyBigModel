# 04. 自注意力机制：全员开会的具体开法

> Day2 学习笔记 · 第四篇（今日重点·收官）｜ 阅读时间约 15 分钟
> 目标：读完这篇，你能用"开会/招聘会"类比讲清自注意力在干什么、Q/K/V 各是什么角色。不推公式，只建立直觉。

---

## 一、先说结论：每个词都在问"谁跟我有关？"

前三篇铺垫完毕，现在打开引擎盖。自注意力（Self-Attention）干的事，用一句话就能说清：

> **每个 token 环顾句中所有其他 token，判断谁和自己最相关，然后按相关程度"加权吸收"它们的信息，更新自己。**

三个动作：**环顾四周 → 判断相关度 → 按比例吸收**。下面用一个句子走一遍全过程。

---

## 二、全程走一遍："它"是怎么锁定"老鼠"的

句子：**「小猫追老鼠，它跑得很快」**

当流水线处理到"它"这个字时，光看"它"本身毫无信息量。要理解这句话，必须知道"它"指的是谁。

**第 1 步：环顾四周。** "它"看看句中的每个词。

**第 2 步：判断相关度（打分）。** "它"给每个词打一个"相关度分数"，直觉上大致是：

```
"它"对全句的相关度打分：
  "老鼠"  ████████░░  0.55   ← 语义上"它"最可能指谁？
  "小猫"  ███████░░░  0.40
  "追"    ███░░░░░░░  0.03
  "跑"    ██░░░░░░░░  0.01
  其他词  ▏           ≈ 0
```

（这些分数最后会归一化成**加起来等于 1 的权重**——相当于"我有限的注意力预算，按比例分配给全句"。）

**第 3 步：按比例吸收。** "它"拿自己原来的向量，按权重混入各词的信息：

```
新的"它" ≈ 自己 0.01 + 老鼠 0.55 + 小猫 0.40 + 其他 ≈ 0
```

走完这一步，"它"的向量就**携带了"老鼠"的语义**。后续层再处理"跑得很快"时，主语是谁已经清楚了。

而在它之外，"追"也在开会吸收"小猫""老鼠"的信息，"跑"也在吸收"它"……**句中每个词都在同时做这三步**——这就是"Self（自）"的含义：全体成员互相成为彼此的信息来源。

再叠加上一篇的知识：这种"开会"在每一层 Block 都发生一次，浅层吸收的是语法搭配，深层吸收的是指代和逻辑——**理解就是这样一层层"滚"出来的**。

---

## 三、Q / K / V：会议桌上的三个角色

上面"打相关分"这一步具体怎么实现？靠三个角色：**Q、K、V**。这是面试和文档里的高频术语，务必建立直觉。

| 角色 | 全称 | 大白话 | 类比（招聘会） |
|---|---|---|---|
| **Q** | Query（查询） | 我要找什么？我的需求 | 你手里的求职意向清单 |
| **K** | Key（键） | 我能提供什么？我的标签 | 每个摊位门口挂的招聘牌 |
| **V** | Value（值） | 我真正携带的内容/干货 | 摊位里能给你的资料 |

匹配过程完整走一遍：

1. "它"拿出自己的 **Q**（"我在找：一个能当主语的动物"）
2. 句中每个词（包括"它"自己）都亮出自己的 **K**（标签）："老鼠"的 K 是"名词·动物·被追方"，"追"的 K 是"动词·动作"……
3. "它"的 Q 和每个 K **对暗号**，相符程度就是相关度分数（→ 上一节的打分表）
4. 按分数加权，把各词的 **V**（干货内容）吸收进来，更新"它"自己

类比成逛招聘会：你带着意向清单（Q）逛全场，扫每个摊位的招聘牌（K），牌子和意向对上的，你就多聊几句、多带走几份资料（V）。

> 🔑 一句话记住三者关系：**Q 去"问"，K 负责"对暗号"，V 是"被取走的干货"。**

### 一个容易困惑的点：Q、K、V 从哪来？

它们**都是同一个词的向量**，只是分别乘了三套不同的变换参数（三副不同的"滤镜"），让同一个词在会场上扮演三重角色：

- 戴上"需求滤镜" → 得到 Q
- 戴上"招牌滤镜" → 得到 K
- 戴上"干货滤镜" → 得到 V

三套滤镜的参数从哪来？**训练学出来的**。模型在海量文本中反复练习"谁该关注谁"，不断调整这三套滤镜——所以微调模型时（Step10），调的很大一部分就是这些参数。

## 四、多头注意力（Multi-Head）：一场会不够，开好几场

一句话里的"关联"不止一种：指代关系、语法搭配、情感倾向、因果逻辑……一场会议装不下所有侧面。

于是 Transformer 同时开**好几场平行的会**（每一场叫一个"头"，Head）：

- 头 1 专门盯指代："它" ↔ "老鼠"
- 头 2 专门盯语法："追" ↔ 主语宾语搭配
- 头 3 专门盯语义相似性、情感……

最后把各场的结论汇总合并。类比：公司决策不开一场大杂烩大会，而是**分成多个专项小组**，各查各的，最后合并报告。

工程上看到的"模型有 32 个注意力头"，指的就是同时开 32 场专项会。这也是个纯参数配置，知道概念即可。

## 五、工程落点：这三个概念什么时候会见到

| 你会遇到的说法 | 对应本篇哪个概念 |
|---|---|
| "attention 可视化 / 看模型关注了哪" | 第二节的相关度权重（实操 3 的 BertViz 就是画这个） |
| "d_model=4096, n_heads=32" | V 向量的维度、并行开几场会 |
| "微调 / LoRA" | 大量调整的就是 Q/K/V 的滤镜参数 |
| "长文本贵、注意力平方开销" | Q 要和**所有** K 两两对暗号，长度翻倍 → 对暗号次数×4 |

## 六、Day2 全篇总结（四篇串起来）

1. **01 为什么需要 Transformer**：RNN 串行慢、传话会忘 → 注意力让全员直连 + 并行；代价是平方级开销
2. **02 整体架构**：五站流水线——分词 → Embedding（语义地图）→ 位置编码（座位号）→ N 层 Block → 输出层（概率分布）
3. **03 三大架构**：Encoder 只读、Encoder-Decoder 读+写、**Decoder-only 只写接龙**——主流 LLM 的选择，赢在任务统一和数据白嫖
4. **04 本篇**：自注意力 = 每词环顾四周、按相关度加权吸收；**Q 问、K 对暗号、V 是干货**；多头 = 多场专项会议

> 四篇合起来的那句话：**Transformer 让所有 token 全员开会、两两直连、并行加工，每一层都让理解更立体——这就是"预测下一个 token"之所以可能的全部底气。**
