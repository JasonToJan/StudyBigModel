# 02. Transformer 整体架构：一段文字在模型里的旅程

> Day2 学习笔记 · 第二篇 ｜ 阅读时间约 15 分钟
> 目标：读完这篇，你能画出"一段文字从进入模型到变成下一个 token 预测"的完整流程图，并说清每站是干嘛的。

## 一、先说结论：模型是一座"分层加工的工厂"

上一篇说了 Transformer 是乐高积木底座。今天把整套积木拼起来，看看**一段文字从进门到出门**要经过哪几站。

好消息是：整条流水线只有 5 站，每站干的事用大白话都能讲清楚。

```
你的文本："今天天气真好"
   │
   ▼ ① 分词（Tokenizer）—— Day1 已学，文字切成 token 编号
 token 序列:  [30214, 12853, ...]
   │
   ▼ ② Embedding —— 每个 token 变成一串数字（向量）
 一排"数字坐标"
   │
   ▼ ③ 位置编码 —— 给每个坐标贴上"我是第几个词"的标签
 带座次的向量
   │
   ▼ ④ N 层 Transformer Block —— 主车间，反复"开会 + 消化"
 层层加工后的向量
   │
   ▼ ⑤ 输出层 —— 对词表里每个 token 打分
 概率分布: "好" 85%, "美" 6%, "糟" 0.1%, ...
   │
   ▼ 挑一个 token 输出 → 拼回输入 → 回到 Day1 的自回归循环
```

下面逐站参观。

## 二、第 ② 站 Embedding：把词变成几何空间里的"点"

模型只认数字。Tokenizer 把文字变成了编号，但"30214"只是一个门牌号，**不携带任何含义**——30213 号旁边不是意思相近的词，只是词表里的邻居。

Embedding 的任务：**给每个 token 发一套几何坐标**（一个长数字串，专业名词叫"向量"）。

### 类比：把所有词钉在一张巨大的地图上

想象一张几千维的"语义地图"，每个词被钉在某个位置上，而**意思相近的词，距离就近**：

- 「猫」「狗」「宠物」挤在同一片街区
- 「国王」「女王」「皇帝」住另一个区
- 「猫」和"光合作用"隔着整张地图

更妙的是，地图上还发现了惊人的规律，比如经典例子：

```
"国王" 的坐标 − "男人" 的坐标 + "女人" 的坐标 ≈ "女王" 的坐标
```

语义关系变成了**几何关系**（距离、方向都可以用数学计算）。这就是模型"理解"词义的方式——不是查词典，而是看谁和谁在地图上住得近。

### 工程落点（重要）

你未来会大量遇到的 **embedding 模型**（如 bge 系列）就是只保留这座"语义地图"的工具：

- 把两段文字都转成向量，**算距离** → 距离近 = 语义相近
- 这就是"语义搜索"的原理：搜"怎么退货"，能找到没出现"退货"二字但讲"售后流程"的文档
- RAG（05 模块）的地基技术，今天先埋个种子

顺带一个术语：向量的长度叫**维度**。主流模型的每个 token 用几千个数字表示（如 4096 维）——数字越多，这张地图能刻画的语义细节越丰富。

## 三、第 ③ 站 位置编码：开会也要有座次

上一篇说过，注意力是"全员开会、两两直连"。但这带来一个新问题：

**开会的机制天然不关心谁先谁后。** 把「猫吃鱼」和「鱼吃猫」的词全部倒开会，对注意力来说——同样的词、同样的两两互动，凭什么意思不同？

可语序明明至关重要。所以 Transformer 在开会前，先做一件事：

> 给每个位置的 token **贴一张"我是第几号"的位置标签**（把位置信息融入向量）。

类比：进会议室先发座位号。之后每个词在开会时不仅知道"我是谁"，还知道"我在第几排"，语序信息就不会丢。

一个值得知道的细节：位置标签的**个数有上限**（比如"最多发 32768 个座次号"）——这也是上下文窗口有限的原因**之一**（另一个更硬的原因是上一篇讲的平方级计算量）。有些模型用的"旋转位置编码（RoPE）"可以外推更长座次，你只需要知道：**窗口大小 = 模型出厂时设计的座次上限**。

---

## 四、第 ④ 站 Transformer Block：主车间，反复"开会 + 消化"

带好座次、拿着语义坐标的 token 们，进入真正的加工车间。每层车间（一个 Block）干两件事：

```
① 注意力层：开会 —— 词与词之间交换信息
        ↓
② 前馈网络（FFN）：回去消化 —— 每个词独自加工刚吸收的信息
        ↓
（每层还配两个"保命设计"：残差连接防记忆丢失、层归一化稳住数值——
  知道名字即可，工程上你几乎不会直接操作它们）
```

类比：一群员工（token）先开一轮全体大会交换情报，再回各自工位独立消化；然后进下一层楼，再开会、再消化……重复几十次。

### 为什么层数越多模型越强？

主流模型堆了几十层甚至上百层 Block。直观理解：

- **浅层**车间处理的偏底层信息：语法、词性、局部搭配（"真"后面接"好"很合理）
- **深层**车间处理的偏高层信息：语义、指代、逻辑关系（"它"指的是谁、这段话的情感倾向）

层数越多，模型能对文本做的"加工轮次"越多，理解就越立体。所谓 **72B、405B 参数**，绝大部分就分布在这些车间的注意力层和 FFN 里——参数量 ≈ 工厂的"设备总量"。

---

## 五、第 ⑤ 站 输出层：一场全员选举

走出最后一层车间，每个 token 身上都浓缩了整句话的上下文信息。模型拿**最后一个位置**的向量（它见过全部输入），做最后一件事：

> 对词表里**每一个**候选 token 打分，换算成概率分布。

比如输入"今天天气真"，输出可能是：

```
"好" → 82%    "美" → 7%    "不" → 4%    "热" → 2%    ……其余几万个 token 分剩下 5%
```

这个概率分布就是 Day1 说的"预测下一个 token"的真身。**至于从分布里怎么挑**（永远挑最高分？还是掷骰子？挑得多随机？）——那是 Day3 推理参数（temperature、top_p）的主题，明天见。

## 七、本篇小结

1. 五站流水线：**分词 → Embedding → 位置编码 → N 层 Block → 输出层**
2. Embedding 把词钉在"语义地图"上，**意思相近 = 距离相近**，语义关系变成可计算的几何关系——语义搜索/RAG 的根基
3. 位置编码给 token 发"座位号"，否则注意力分不清语序；座次上限是窗口限制的原因之一
4. Block = **开会（注意力）+ 消化（FFN）**，浅层管语法、深层管语义；参数量主要堆在这里
5. 输出层对全词表打分得到概率分布——"预测下一个 token"的真身，怎么挑留给 Day3
