# 03. top_p / top_k：先把烂选项踢出局，再谈抽签

> Day3 学习笔记 · 第三篇 ｜ 阅读时间约 10 分钟
> 目标：读完这篇，你能分清 top_p / top_k 各自怎么圈定候选池、它们和 temperature 的分工，以及为什么官方建议"别同时拧到极端"。

---

## 一、先说结论：温度管"怎么抽"，top_p / top_k 管"谁能上桌"

上一节看到高温的隐患：众生平等后，几万个"杂牌 token"也分到了蛋糕，乱码风险随之而来。

那就换一个思路：**与其在全体词表里调比例，不如先把烂选项踢出局，只在头部候选里抽签。**

这就是 top_k 和 top_p 的使命。三组旋钮的分工一句话记牢：

> 🔑 **temperature 管"怎么分蛋糕"，top_p / top_k 管"谁有资格上桌"。**

---

## 二、top_k：按"名额"圈定——只留前 k 名

规则最简单：**只保留打分前 k 名，其余全部出局**。

设 top_k = 3，还是那张表：

```
候选打分：好 82% ｜ 美 7% ｜ 不 4% ｜ 热 2% ｜ 其余几万个共 5%
                 └────── 上桌 ──────┘  └────── 直接没资格 ──────┘
```

"热"哪怕还有 2%，也和几万杂牌一起被请出场。抽签只在"好 / 美 / 不"之间进行。

**问题：名额是死的，任务却是活的。**

- 答案非常明确时（如数学题），前 3 名可能就占了 99.9%——top_k=3 形同虚设，纯属白设
- 答案很开放时（如起名），前 50 名概率都很接近——只留 3 个太粗暴，多样性直接被掐死

需要一种**能随情况伸缩**的圈定方式——这就是 top_p。

---

## 三、top_p：按"累计概率"圈定——名额随局势伸缩

top_p（学名**核采样，Nucleus Sampling**）的规则：

> 从第 1 名开始累加概率，**加到刚够 p** 为止，凑够这些人上桌；其余出局。

设 top_p = 0.9，还是那张表：

```
好 82%          → 累计 82%，还没够
好 + 美 7%      → 累计 89%，还差一点
好 + 美 + 不 4% → 累计 93% ≥ 90%，够了！
→ 上桌名单：好、美、不（"热"和杂牌出局）
```

**妙处在于：名额是动态的。**

- 概率**集中**时（答案明确）：前 2~3 名就凑够 90%，候选池自动缩得很小——安全
- 概率**分散**时（创意任务）：要几十上百个词才凑够 90%，候选池自动放大——多样

对比类比：

| | 类比 | 特点 |
|---|---|---|
| top_k | 按名额录取：前 3 名上 | 死板，不看局势 |
| top_p | 按分数线录取：凑够 90% 就停 | 灵活，题简单时门槛自动收紧 |

因为 top_p 更聪明，**现代模型和 API 默认圈定方式基本都用 top_p**；top_k 你知道概念即可（部分平台甚至不开放这个参数）。

---

## 四、与 temperature 的配合：先圈人，再分蛋糕

两个旋钮一起工作时，流程是：

```
全体词表 → [top_p / top_k 圈定候选池] → [temperature 在池内分配概率] → 掷骰子
```

**常见的搭配速查：**

| 场景 | temperature | top_p | 效果 |
|---|---|---|---|
| JSON 抽取 / 代码 | 0 ~ 0.2 | 1.0（不启用）或 0.9 | 温度低已经足够稳，基本用不到圈人 |
| 客服对话 | 0.2 ~ 0.4 | 0.9 | 稳中有变化 |
| 创意写作 | 0.9 ~ 1.1 | 0.95 | 放开分蛋糕，但杂牌仍被挡在门外 |

**一条重要的工程军规**（各官方文档反复强调）：

> **temperature 和 top_p 不要同时大幅调整，调一个就好。**

两个都拧向极端，效果会互相纠缠、难以解释也更难排查。实践中的保守策略：**top_p 保持默认（0.9 或 1.0），需要调"灵活度"时只动 temperature**。等有了明确理由（比如输出总冒生僻字），再去压低 top_p。

---

## 五、工程落点

1. **排查口诀**：输出混入乱码 / 生僻字 / 离谱词 → 先压 temperature；还不行 → 压 top_p（0.9 → 0.7）
2. 各平台参数开放程度不同：top_p 几乎都有；top_k 有的不开放——迁移代码时注意兼容
3. 圈人逻辑（top_p）发生在分蛋糕（temperature）**之前**，所以两者数学上会相互作用——这也是"别同时拧到极端"的根本原因

---

## 六、本篇小结

1. 分工口诀：**temperature 管"怎么分蛋糕"，top_p / top_k 管"谁能上桌"**
2. **top_k** = 固定名额留前 k 名（死板）；**top_p** = 累计概率凑够 p 就停（动态伸缩，现代默认）
3. top_p 妙处：答案明确时池子自动缩小保安全，创意场景池子自动放大保多样
4. 军规：**两个旋钮别同时拧到极端**；保守策略是只动 temperature
