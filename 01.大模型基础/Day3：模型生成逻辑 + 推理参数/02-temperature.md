# 02. temperature：拧动概率表的"贫富差距"

> Day3 学习笔记 · 第二篇（今日重点）｜ 阅读时间约 12 分钟
> 目标：读完这篇，你能讲清 temperature 到底改了概率表的什么、0.1 和 1.5 的世界差在哪，并破除"温度=智力"的常见误区。

---

## 一、先说结论：温度不改排名，只改差距

temperature（温度）是作用在上一节那张概率表上的第一个旋钮。它有一个非常反直觉的特性：

> **无论温度怎么调，候选 token 的排名永远不变**——"好"永远比"美"概率高。
> **变的是它们之间的差距**：低温把差距拉大，高温把差距抹平。

类比：温度调节的是这张概率表的**"贫富差距"**——

- **低温**：赢家通吃，第一名拿走几乎所有蛋糕，其余喝汤（贫富悬殊）
- **高温**：大锅饭，人人分一口，第一名不再垄断（趋于平均）

---

## 二、同一张表，三种温度下的命运

还是那句输入"今天天气真"，固定打分不变，只拧温度：

```
原始打分：好 8.0 ｜ 美 4.5 ｜ 不 3.8 ｜ 热 2.5 ｜ 其余更低……
```

| | T = 0.1（低温） | T = 1.0（正常） | T = 2.0（高温） |
|---|---|---|---|
| "好" | ≈100% | 82% | ≈58% |
| "美" | ≈0% | 7% | 16% |
| "不" | ≈0% | 4% | 13% |
| "热" | ≈0% | 2% | 8% |
| 其余杂牌 | ≈0% | 5% | 5%+，且杂牌也在涨 |
| 世界观 | 第一名垄断一切 | 正常人间 | 众生平等，乱字横行 |

三个温度，三种世界：

- **T → 0**：概率表"塌缩"成一个点——第一名通吃。**此时采样退化成了贪心解码**（这就回答了上一节的悬念：贪心其实是温度趋近 0 的特例）
- **T = 1.0**：模型"原生"的概率分布，大多数 API 的默认值就在这附近
- **T = 2.0**：次优词、生僻词都有可观的机会被抽中——输出开始出现跑题、乱码、胡言

---

## 三、温度的两端：各自适合什么活

### 低温世界（0 ~ 0.3）

- 输出稳定、保守、可复现，几乎永远给"最标准"的答案
- 适合：**代码生成、数学、信息抽取、分类打标、客服标准问答**——这些任务要的是"正确"，不是"惊喜"
- 副作用：表达单调，同样的问法永远得到同一套话

### 高温世界（0.7 ~ 1.5）

- 输出多样、有新意，经常冒出意料之外的组合
- 适合：**头脑风暴、起名、写诗写文案、生成多版本候选**
- 副作用：翻车率上升——跑题、前后矛盾、一本正经地胡说

### 🔑 破除最大的误区：温度不是"智力旋钮"

> 调低温度，模型**不会变得更聪明**，只是**更保守**（不敢选次优答案）；
> 调高温度，模型**也不会更笨**，只是**更敢赌**。

模型的"能力上限"由参数和训练决定，温度只控制"在能力范围内怎么挑答案"。所以：

- 数学题答错了，调低温度不会让它突然会做——只是让它更稳定地展示自己本来的水平
- 创意不够，调高温度是撒骰子碰运气——碰得到惊喜，也碰得到车祸

## 四、工程落点

1. **经验配置速查**：

   | 任务 | 推荐温度 |
   |---|---|
   | 抽取 / 分类 / JSON 输出 | 0 ~ 0.2 |
   | 客服 / 代码 | 0.1 ~ 0.3 |
   | 常规对话 | 0.5 ~ 0.7 |
   | 创意写作 / 起名 | 0.8 ~ 1.2 |

2. **temperature=0 ≠ 100% 可复现**。低温已经"接近确定性"，但 GPU 浮点运算本身存在极小的非确定性，极端情况下仍可能出现一字之差。文档里说"温度 0 输出确定"，工程上要理解成"几乎确定"。真要严格复现，配合固定 **seed** 参数。

3. **评测与自动化流水线用低温，产品对话适当加温**。跑批量评测时必须低温（否则结果抖动没法比较）；面向用户的闲聊可以加温提升"活人感"。

4. 各家 API 的温度范围不同（有的 0~1，有的 0~2），跨平台迁移时要换算，别直接照抄数字。

---

## 五、本篇小结

1. temperature **不改排名，只改差距**：低温贫富悬殊（赢家通吃），高温众生平等（乱字横行）
2. T→0 时采样退化为贪心；T=1 是原生分布；再高就开始抽到烂牌
3. 温度**不是智力旋钮**：低温=保守，高温=敢赌，能力上限与温度无关
4. 工程速查：抽取/代码用低温，创意用高温；严格复现配合 seed
