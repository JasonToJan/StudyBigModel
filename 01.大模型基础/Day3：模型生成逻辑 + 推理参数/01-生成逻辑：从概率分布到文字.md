# 01. 生成逻辑：从概率分布到文字，最后一公里怎么走

> Day3 学习笔记 · 第一篇 ｜ 阅读时间约 12 分钟
> 目标：读完这篇，你能说清模型"打完分"之后发生什么、贪心和采样两种策略的区别，以及为什么"同样的输入，输出可能不同"。

---

## 一、先说结论：模型给的不是字，是一张中奖概率表

Day2 最后一站讲到：输出层对词表里每个 token 打完分，得到一个**概率分布**。比如输入"今天天气真"：

```
"好"  → 82%     ← 人气王
"美"  →  7%
"不"  →  4%
"热"  →  2%
……其余几万个 token 分剩下 5%
```

但注意：**模型到这一步就停手了**。它只负责报出这张概率表，至于**最后把哪个 token 交给你**，是另一个环节决定的——这个环节叫**采样策略（Decoding Strategy）**，也是今天所有推理参数的舞台。

一个必须纠正的直觉：模型内部并没有"标准答案"这个概念。每个候选 token 都有概率被选中，差别只是概率大小。

---

## 二、两种基本策略：抄第一名 vs 按人气抽签

拿到概率表，最朴素的有两种挑法。

### 策略 A：贪心解码（Greedy）——永远抄第一名

每一步都选概率最高的 token，不做任何随机。

- 输入"今天天气真" → 一步不差地选"好"
- **同样的输入，永远得到完全相同的输出**（确定性，工程师最爱）

### 策略 B：随机采样（Sampling）——按概率掷骰子

做一个 82% / 7% / 4% / 2%…… 的转盘，转到谁用谁。

- 大概率抽到"好"，但**偶尔**会抽到"不"、"美"这类次优选项
- 同样的输入，**每次输出可能不同**

| | 贪心 | 采样 |
|---|---|---|
| 确定性 | 每次一样 | 每次可能不同 |
| 稳定性 | 高 | 低（可能抽到烂选项） |
| 多样性 | 零（容易死板、复读） | 高 |

---

## 三、为什么不能只用贪心？——呆板的悖论

直觉上贪心最靠谱："永远选最好的"怎么会错？但它有个致命弱点：**千篇一律，且容易复读机**。

想一个写故事的场景：贪心策略永远选"统计上最安全"的下一个词——于是：

> "阳光明媚的早晨，阳光明媚的早晨，阳光明媚的早晨……"

因为每一步都挑"最像的前文延续"，输出会不断自我强化，陷入复读循环。创意任务里，"第二、第三名"的词往往才是惊喜的来源——全都抄第一名，就永远没有惊喜。

而反过来，**纯随机采样**又太野：那 5% 的"其余 token"里全是生僻字、乱码风险，偶尔抽中一个，整句话就毁了。

> 🔑 两难由此诞生，今天的主角们登场：
> **贪心太死板，采样太随意 → 我们需要旋钮，在这两者之间精确调节。**

这就是 temperature、top_p 的使命。记住这个动机，后面每个参数都好理解。

---

## 四、顺手收下两个高频名词卡片

**logits（原始分数）**：输出层打分的"毛分"，可以是任意数值（如 8.3、-2.1），不能直接当概率用。

**softmax（归一化）**：把毛分"换算成加起来等于 1 的百分比"的数学操作，相当于把考卷分数换算成中奖概率。换算前后**排名不变**，但分数之间的差距会被拉伸或压缩——这个"拉伸压缩"的力度，正是明天 temperature 要动手脚的地方（伏笔）。

另一个工程词汇 **finish_reason（结束原因）**——生成结束的方式有几种，API 会如实汇报：

| 值 | 含义 | 工程上怎么办 |
|---|---|---|
| `stop` | 正常说完（模型自己决定闭嘴） | 一切正常 |
| `length` | 撞到 max_tokens 上限被掐断 | 判断是否需要调大 max_tokens 或分页续写 |
| `content_filter` | 被安全策略拦截 | 按业务处理 |

Day1 说过"答到一半戛然而止"，看到 `length` 你就知道该查谁了。

---

## 五、工程视角：为什么"每次输出不同"值得在意

做产品时，采样策略直接影响三件事：

1. **可复现性**：贪心/低温 = 同样输入同样输出，方便测试和调试；高温则每次不同，要靠固定 seed 来复现问题
2. **缓存友好**：输出确定（贪心）时，相同请求可以直接命中缓存，省真金白银
3. **测试的坑**：你的 prompt 改了 1 个字，评测效果却"时好时坏"——先看温度是不是太高，别急着怀疑 prompt

> 顺便解开 Day1 留的最后悬念：**"同一个问题每次答案不一样"，不是模型"有想法"，而是采样在按概率掷骰子。** 贪心或温度调 0 后，掷骰子基本停止。

---

## 六、本篇小结

1. 模型输出的是**概率表**，不是字；把表变成字的是**采样策略**
2. 两种基本策略：**贪心**（永远第一名，确定但呆板）vs **采样**（按概率抽签，多样但易翻车）
3. 纯贪心会复读，纯采样会抽烂牌 → 需要旋钮在两者之间调节——这就是推理参数的使命
4. 名词卡：logits（毛分）→ softmax（换算成概率）；finish_reason 里 `length` = 被截断
5. 输出不确定性来自采样，不来自模型"有想法"
