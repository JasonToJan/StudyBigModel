## 1. 模型输出的概率分布，是怎么变成最终文字的？（贪心 vs 采样）

模型对词表打分（logits → softmax）得到概率表后，**采样策略**决定挑哪个 token：

- **贪心解码**：永远选概率第一名——确定性强、可复现，但千篇一律、容易复读
- **随机采样**：按概率掷骰子——有多样性，但可能抽到低质量 token

两难（贪心太死板、采样太随意）催生了调节旋钮（temperature / top_p）。

## 2. temperature 拧的是什么？调高/调低分别发生什么？

拧的是概率表的**"贫富差距"**（排名永远不变，变的是差距）：

- **低温**：差距拉大，赢家通吃 → 采样退化成贪心；稳定保守，适合代码/抽取/客服
- **高温**：差距抹平，众生平等 → 次优词生僻词都有机会；多样有创意，也易乱码跑题

最大误区：**温度不是智力旋钮**——低温只是保守，高温只是敢赌，能力上限与温度无关。

## 3. top_p（核采样）在干什么？它和 temperature 怎么配合？

top_p = 从概率第 1 名开始累计，**加到刚够 p 就停**，这些人上桌，其余出局。

妙处：名额动态伸缩——答案明确时前两三名就凑够，池子自动缩小保安全；创意场景要几十个词才凑够，池子自动放大保多样。

配合分工：**top_p/top_k 先圈定"谁能上桌"，temperature 再在池内"分蛋糕"**。军规：别同时拧到极端，保守策略是 top_p 保持默认、只动 temperature。

## 4. max_tokens、stop、repetition_penalty 这些常用参数各管什么？

- **max_tokens**：输出天花板/保险丝——超了 `finish_reason=length` 被截断（设大不费钱，设小出事故，如 JSON 半截被掐）
- **stop**：自定义"闭嘴暗号"——生成中出现指定字符串就停；续写场景防止模型替你把下一句话也写了
- **penalties（repetition/frequency/presence）**：治复读机——对出现过的 token 施加惩罚；分寸要拿捏（调过头模型会刻意绕关键词），**代码/JSON 等需要重复的任务必须关闭**

## 5. 给你一个真实场景（客服问答 / 创意文案 / 代码生成），你会怎么配参数？

| 场景 | 配置 | 理由 |
|---|---|---|
| 客服问答 | temperature 0.1~0.3，top_p 默认 | 稳定准确第一 |
| 创意文案 | temperature 0.8~1.2，top_p 0.95 | 放开分蛋糕，top_p 挡烂牌 |
| 代码生成 | temperature 0~0.2，**penalties 全关**，max_tokens 留足 | 严谨 + 代码需要重复（变量名），且防截断 |
